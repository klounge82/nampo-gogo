# 남포고고 외부 진단용 테스트 계정 제공 및 운용 계획서 (EXTERNAL_SECURITY_TEST_ACCOUNTS_PLAN_KO)

**문서 버전**: v1.0  
**작성일자**: 2026-08-02  

---

## 1. 계정 운용 기본 원칙
1. **실제 계정 절대 사용 금지**: 남포고고 서비스의 실제 사업자(OWNER) 및 개인 고객(CUSTOMER) 계정은 진단용으로 절대 제공하지 않습니다.
2. **보안 진단 전용 계정 발급**: 외부 진단업체 전용으로 발급된 5종의 테스트 계정만 사용하여 점검을 진행해야 합니다.
3. **격리된 테스트 데이터 연동**: 발급된 계정에는 전용 가짜 매장(Dummy Store) 및 테스트 예약/리뷰 데이터만 매핑되어 있습니다.
4. **진단 종료 후 즉시 폐기**: 진단 완료 후 발급된 모든 계정은 비밀번호 변경 및 계정삭제(`status='withdrawn'`) 처리됩니다.

## 2. 진단용 테스트 계정 5종 명세

| 계정 유형 | 역할 (Role) | 매장 권한 | 비고 |
| :--- | :--- | :--- | :--- |
| **1. CUSTOMER 일반회원** | `CUSTOMER` (`member`) | 없음 | 일반 이용자 권한 (코스 추천, 예약 신청, 리뷰 작성) |
| **2. BUSINESS STAFF** | `BUSINESS` (`staff`) | 점포 A (`store_sec_01`) | 현장 직원의 예약 조회 및 현장확인 권한 |
| **3. BUSINESS MANAGER** | `BUSINESS` (`manager`) | 점포 A (`store_sec_01`) | 매장 관리자의 예약 승인/거절 및 설정 권한 |
| **4. BUSINESS OWNER** | `BUSINESS` (`owner`) | 점포 A (`store_sec_01`) | 점주의 권한 (매장 정보 변경, 정산, 권한 부여) |
| **5. ADMIN 관리자** | `ADMIN` (`admin`) | 전체 시스템 | 플랫폼 전체 관리자 권한 (사업자 승인, 통계 등) |

*※ 계정별 ID/비밀번호 정보는 계약 체결 후 안전한 보안 채널(암호화 ZIP / 원타임 노드)을 통해 별도 전달됩니다.*

## 3. 계정 환경 구성 방식 비교 (Staging vs Production)

진단 수행 시 사용할 환경 구성 옵션 2가지를 제시합니다. **안전성을 위해 [옵션 A: Staging 전용 환경]을 적극 권장합니다.**

### [옵션 A] Staging 전용 독립 환경 (권장)
- **구성**: 운영 DB와 100% 분리된 별도 Staging Database 및 Staging API Server 구성.
- **장점**:
  - 운영 DB에 대한 영향 0%.
  - 모의 공격 시 데이터 오염 위험이 완벽히 차단됨.
  - 진단 후 DB 전체 초기화(`TRUNCATE` / `DROP`) 용이.
- **단점**: 별도 Staging 환경 인프라 비용 및 배포 작업 필요.

### [옵션 B] Production 운영 환경 진단 (제한적)
- **구성**: 현재 배포된 Railway Production 서버에서 지정된 5개 전용 계정으로만 수행.
- **장점**: 별도 환경 구축 없이 즉시 진단 착수 가능.
- **단점 / 제약사항**:
  - 테스트 계정 이외의 실제 계정에 대한 조작 절대 금지.
  - 가짜 매장(`store_sec_01`) 내부에서만 예약/리뷰 테스트 수행.
  - 진단 종료 후 생성된 테스트 데이터의 수동 정리 필요.
